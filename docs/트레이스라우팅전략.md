# 트레이스 라우팅 전략

## 현재 문제

1. 트레이스가 함수 도형을 관통함
2. 트레이스끼리 겹침
3. 연결이 많은 함수가 중앙에 있어서 주변 트레이스가 혼잡

---

## 1. 전략 원칙

### 원칙 0: 함수 배치 최적화

연결이 많은 함수일수록 트레이스 경로를 짧게 만드는 위치에 배치한다.

**Step 1 — 각 함수의 연결 방향 점수 산출**

각 함수에 대해 4가지 카운트를 구한다:

| 카운트 | 의미 |
|--------|------|
| `extOut` | 타 파일그룹으로 나가는 유출 라인 수 |
| `extIn` | 타 파일그룹에서 들어오는 유입 라인 수 |
| `intOut` | 같은 그룹 내부로 나가는 유출 라인 수 |
| `intIn` | 같은 그룹 내부에서 들어오는 유입 라인 수 |

**Step 2 — 좌우 위치 결정**

좌우 점수를 계산하여 함수를 왼쪽/오른쪽에 배치:

```
rightScore = extOut + intIn
leftScore  = extIn  + intOut
```

| rightScore vs leftScore | 배치 | 이유 |
|-------------------------|------|------|
| rightScore > leftScore | 우측 | 외부 유출 + 내부 유입 → 오른쪽 패드 활용이 유리 |
| leftScore > rightScore | 좌측 | 외부 유입 + 내부 유출 → 왼쪽 패드 활용이 유리 |
| 동점 | 어느 쪽이든 가능 | 총 연결 수 기준으로 바깥쪽 우선 |

**Step 3 — 열 내 행 배치 (바깥쪽 우선)**

Step 2에서 1열(좌측)과 N열(우측)로 나뉜 함수들을 각 열 안에서 행 위치를 결정한다.

**1열(좌측) 그룹** — `leftScore`(`extIn + intOut`) 내림차순 정렬:
- leftScore가 높을수록 그룹 **바깥쪽 행**(1행, 마지막행)에 배치
- 외부 유입 + 내부 유출이 많은 함수가 모서리에 있으면 왼쪽 패드 경로가 짧아짐

**N열(우측) 그룹** — `rightScore`(`extOut + intIn`) 내림차순 정렬:
- rightScore가 높을수록 그룹 **바깥쪽 행**(1행, 마지막행)에 배치
- 외부 유출 + 내부 유입이 많은 함수가 모서리에 있으면 오른쪽 패드 경로가 짧아짐

**행 배정 순서 (지그재그):**
```
정렬된 함수 리스트: [f1, f2, f3, f4, f5, ...]  (점수 내림차순)

배정 위치:
  f1 → 1행   (맨 위)
  f2 → 마지막행 (맨 아래)
  f3 → 2행
  f4 → (마지막-1)행
  f5 → 3행
  ...         (바깥→안쪽으로 채워나감)
```

> 연결이 많은 함수가 열의 양 끝(모서리)에 위치하므로,
> 트레이스가 그룹 내부를 관통할 필요가 줄어듦

### 원칙 1: 트레이스 비겹침 (교차는 허용)

- 트레이스끼리 **평행하게 겹치는 것**은 금지
- 90도 또는 45도 각도로 **교차(crossing)하는 것**은 허용
- 겹침 판정은 그리드 기반으로 수행 (아래 "충돌 판정" 참조)

### 원칙 2: 함수 도형 비관통

- 트레이스는 함수 도형(노드 바운딩 박스)을 절대 통과하지 않음
- 노드 사이의 갭 또는 그룹 외곽 채널을 통해 라우팅

### 원칙 3: 노드패드 수 기준 순차 라우팅

- 노드패드가 가장 많은 함수의 트레이스부터 먼저 그림
- 먼저 그려진 트레이스는 이후 트레이스의 장애물로 취급
- 연결이 많은(=중요한) 함수의 트레이스가 최적 경로를 확보

## 2. 그리드 설계

### 셀 구조

**그리드 셀 크기: 4px** (수정 가능성 있음)

```
  4px
├────┤
┌────┐
│·##·│  · = 오프셋 (1px)
└────┘  # = 트레이스 레인 (2px)
```

- 중앙 **2px** = 트레이스 레인 (트레이스 선이 실제로 그려지는 영역)
- 양쪽 **1px** = 오프셋 (인접 트레이스와의 최소 간격 보장)

### 셀 점유 표현

각 트레이스는 지나가는 그리드 셀을 **방향 정보와 함께** 마킹한다.

하나의 셀에 저장되는 정보:
- 점유 여부 (boolean)
- 점유 방향: 가로(`H`), 세로(`V`), 대각선(`D1`, `D2`)

### 충돌 판정: AND 연산 방식

트레이스끼리 **교차**는 허용하되 **평행 겹침**은 금지해야 한다.

**판정 방법:**
1. 새 트레이스가 지나갈 셀 목록을 계산
2. 각 셀에 대해, 이미 점유된 트레이스의 방향과 새 트레이스의 방향을 비교
3. **두 셀 연속으로 같은 방향이 겹치면** → 충돌 (라우팅 불가)
4. **한 셀만 겹치거나, 다른 방향으로 겹치면** → 교차 (허용)

```
예시: 기존 트레이스가 가로(H)로 점유한 구간

  셀A(H)  셀B(H)  셀C(H)       ← 기존 트레이스 (가로)
  
  새 트레이스가 세로(V)로 셀B를 통과:
  셀B에서 H와 V가 만남 → 1셀만 겹침 → ✅ 교차 허용
  
  새 트레이스가 가로(H)로 셀A~셀B를 통과:
  셀A(H∧H) + 셀B(H∧H) → 연속 2셀 같은 방향 겹침 → ❌ 평행 겹침 금지
```

**요약: 겹침 = AND 연산 결과에서 같은 방향이 연속 2셀 이상**

### 함수 도형의 그리드 마킹

- 함수 도형(바운딩 박스)이 차지하는 셀은 **모든 방향에서 점유**로 마킹
- 어떤 방향의 트레이스든 해당 셀에 진입 불가 → 관통 방지

### 코너 Chamfer (45도 구간)

H(가로)↔V(세로) 전환 시 직각 코너 대신 **45도 대각선(D) 구간을 삽입**한다.

```
직각 코너 (사용 안 함)     Chamfer 코너 (사용)
                          
  ──────┐                   ──────╲
        │                          ╲
        │                           │
        │                           │
```

**Chamfer 크기 계산:**
- H 구간 길이와 V 구간 길이 중 짧은 쪽의 **1/2**
- `chamferLen = min(H길이, V길이) / 2`
- H 구간을 chamferLen만큼 줄이고, V 구간을 chamferLen만큼 줄인 뒤, 그 사이에 D 구간 삽입

```
예시: H=12셀, V=6셀 → chamferLen = min(12,6)/2 = 3셀

  H(9셀)─────╲ D(3셀)
               ╲
                │ V(3셀)
```

## 3. 그리드 스코프 (로컬 vs 글로벌)

각 Phase에서 사용하는 그리드는 **별도로 생성**한다.

### Phase 1 그리드: 파일그룹별 로컬 그리드

- 각 파일그룹마다 **자체 로컬 그리드**를 생성
- 그리드 범위 = 해당 파일그룹의 바운딩 박스 영역만
- 파일그룹 내부 함수 도형만 전방향 점유로 마킹
- 내부 트레이스 라우팅은 이 로컬 그리드 안에서만 경로 탐색

> 파일그룹 하나가 예를 들어 640×400px이면 → 160×100 셀 그리드면 충분.
> 전체 캔버스(8192×8192 등)를 할당할 필요 없음.

### Phase 2 그리드: 그룹 간 글로벌 그리드

- 모든 파일그룹의 **외곽 채널 영역**만 포함하는 그리드
- **채널 폭: 20그리드(= 80px)** — 그룹 간 최소 간격 (하드코딩, 추후 변경 가능)
- 파일그룹 영역 자체를 전방향 점유로 마킹 (그룹 관통 방지)
- Phase 1에서 확정된 내부 트레이스는 이미 그룹 안에 있으므로 글로벌 그리드에 마킹 불필요

```
┌─────────────────────────────────────┐
│          글로벌 그리드 영역            │
│                                     │
│   ┌─────────┐     ┌─────────┐      │
│   │ 그룹 A   │     │ 그룹 B   │      │
│   │(전방향   │ ←채널→│(전방향   │      │
│   │ 점유)    │  공간 │ 점유)    │      │
│   └─────────┘     └─────────┘      │
│                                     │
│   ┌─────────┐                       │
│   │ 그룹 C   │                       │
│   └─────────┘                       │
└─────────────────────────────────────┘

Phase 2 트레이스는 채널 공간에서만 경로 탐색
```

## 4. 라우팅 순서

### Phase 1: 파일그룹 내부 트레이스

- 각 파일그룹별로 **같은 파일 내 함수 간 호출**을 먼저 라우팅
- **로컬 그리드** 사용 (해당 그룹 영역만)
- 라우팅 실패 시 열 간격 확장 → 재라우팅 (섹션 5 참조)

### Phase 2: 파일그룹 외부 트레이스

- 서로 다른 파일그룹 간의 연결을 라우팅
- **글로벌 그리드** 사용 (그룹 바깥 채널 공간)

---

## 5. 라우팅 실패 시 재귀 복구

Phase 1(로컬 그리드) 라우팅 중 경로를 찾을 수 없으면, 단계적으로 복구를 시도한다.

### Step A: 열 간격 확장

1. 라우팅 실패한 열 간격을 **+2그리드(= 8px)** 만큼 확장
   - 예: 1열↔2열 기본 간격 40px → 48px
2. 로컬 그리드 재생성 (확장된 크기 반영)
3. 해당 그룹의 트레이스를 **처음부터 재라우팅**
4. 그룹 크기도 확장에 맞게 재조정

### Step B: 함수 배치 재조정

열 간격 확장만으로 해결되지 않으면 (확장 2회 초과 시), 해당 그룹 내 함수 배치를 변경한다:

1. 라우팅 실패를 유발한 함수의 행 위치를 **교환(swap)**
   - 충돌이 발생한 두 트레이스의 소속 함수 중, 행 위치를 바꾸면 경로가 단축되는 쌍을 탐색
2. 배치 변경 후 로컬 그리드 **초기화** → 해당 그룹 전체 재라우팅
3. 여전히 실패 시 다른 함수 쌍으로 swap 시도

### 복구 흐름도

```
라우팅 실패 발생
  │
  ├─ Step A: 열 간격 +2그리드 확장
  │   ├─ 성공 → 완료
  │   └─ 실패 (확장 2회 초과)
  │       │
  │       ├─ Step B: 함수 행 위치 swap
  │       │   ├─ 성공 → 완료
  │       │   └─ 실패 (swap 후보 소진)
  │       │       │
  │       │       └─ Step A로 복귀 (확장 카운터 리셋, 새 배치로 재시도)
  │       │
  │       └─ (최종 실패: 현재 배치에서 가능한 최선의 경로 사용)
  └─
```

> Step A(간격 확장)와 Step B(배치 변경)를 재귀적으로 교차 시도하여
> 밀집된 그룹에서도 라우팅 가능한 배치 + 간격 조합을 자동으로 탐색

## 6. 실행 절차 요약

```
1. 함수 배치 (layout) — 원칙 0 적용
   ├─ 각 함수의 연결 방향 카운트 산출 (extOut, extIn, intOut, intIn)
   ├─ 좌우 점수 계산 (rightScore = extOut+intIn, leftScore = extIn+intOut)
   ├─ 점수 비교로 1열(좌측) / N열(우측) 배정
   └─ 각 열 내에서 해당 점수 내림차순 → 바깥쪽 행부터 지그재그 배정

2. 함수 노드패드 할당
   ├─ 인입: 왼쪽 우선 → 위쪽 오버플로우
   └─ 유출: 오른쪽 우선 → 아래쪽 오버플로우

3. Phase 1: 내부 트레이스 라우팅 (그룹별 로컬 그리드)
   ├─ 해당 그룹의 로컬 그리드 생성 (그룹 바운딩 박스 크기)
   ├─ 함수 도형 영역을 전방향 점유로 마킹
   ├─ 연결 수 기준 내림차순으로 함수 순회
   ├─ 그룹 내부 엣지에 대해 경로 탐색
   ├─ H↔V 코너에 chamfer(D) 삽입 (크기 = min(H,V)/2)
   ├─ 경로 확정 → 로컬 그리드에 방향(H/V/D) 포함 마킹
   ├─ 충돌 판정: AND 연산 → 같은 방향 연속 2셀 이상이면 충돌
   ├─ 라우팅 실패 시:
   │   ├─ Step A: 열 간격 +2그리드 확장 → 그리드 재생성 → 재라우팅
   │   └─ Step B: 함수 행 위치 swap → 그리드 초기화 → 재라우팅
   └─ 결과: RoutedEdge[] (내부)

4. Phase 2: 외부 트레이스 라우팅 (글로벌 그리드)
   ├─ 글로벌 그리드 생성 (채널 폭 = 20그리드/80px)
   ├─ 각 파일그룹 영역을 전방향 점유로 마킹
   ├─ 그룹 간 엣지에 대해 채널 공간 경로 탐색
   ├─ H↔V 코너에 chamfer(D) 삽입 (크기 = min(H,V)/2)
   ├─ 경로 확정 → 글로벌 그리드에 방향(H/V/D) 포함 마킹
   ├─ 충돌 판정: AND 연산 → 같은 방향 연속 2셀 이상이면 충돌
   └─ 결과: RoutedEdge[] (외부)
```

## 결정 사항

- [x] 점유 자료구조: **2D 그리드 + 방향 정보**
- [x] 그리드 셀 크기: **4px** (레인 2px + 양쪽 오프셋 1px)
- [x] 충돌 판정: **AND 연산 → 같은 방향 연속 2셀 이상이면 충돌**
- [x] 교차 허용: **다른 방향이거나 1셀만 겹치면 OK**
- [x] 함수 도형: **전방향 점유로 마킹 (관통 불가)**
- [x] 그리드 스코프: **Phase 1 = 그룹별 로컬 그리드, Phase 2 = 글로벌 그리드**
- [x] 라우팅 순서: **내부 트레이스 → 외부 트레이스**
- [x] 라우팅 실패 시: **Step A(열 간격 확장) ↔ Step B(함수 배치 swap) 재귀 복구**

- [x] 그룹 간 채널 폭: **20그리드(= 80px)** 하드코딩 (추후 변경 가능)
- [x] 45도 구간: **코너 chamfer로 사용** (H↔V 전환 시 D 삽입, 크기 = min(H,V)/2)

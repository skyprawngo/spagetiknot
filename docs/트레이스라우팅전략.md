# 트레이스 라우팅 전략

## 설계 방향

자동 라우팅의 복잡성과 가시성 문제를 해결하기 위해,  
**기본은 직선**으로 단순하게 표시하고  
**사용자가 직접 경로를 조형**하는 방식으로 전환한다.

---

## 1. 레이어 구조: 베이스 선 + 아트웍 오버레이

각 트레이스는 항상 두 레이어로 구성된다.

```
┌──────────────────────────────────────┐
│  아트웍 오버레이 (Artwork Overlay)    │  ← 사용자가 조형한 H-V 선분 체인 + D chamfer
│  (없으면 투명)                        │
├──────────────────────────────────────┤
│  베이스 선 (Base Line)                │  ← 패드–패드 직선 데이터, 항상 유지
└──────────────────────────────────────┘
```

- **베이스 선**: `fromPad → toPad` 직선. 삭제되지 않고 항상 존재.
- **아트웍 오버레이**: 버텍스 + H-V 선분 체인. 베이스 선 위에 덮어씌움.
- 아트웍 오버레이가 없으면 베이스 직선이 표시된다.

---

## 2. D(대각선)의 본질: 구조가 아닌 장식

D는 H(가로)와 V(세로) 사이를 잇는 **45도/135도 chamfer**이며, 순수하게 **시각적 장식**이다.

- **구조적으로**: 모든 D는 H-V 또는 V-H로 대체 가능
- **목적**: 직각 꺾임을 부드럽게 표현하여 트레이스 가시성 향상
- D는 H와 V 사이에만 삽입 가능하며, 독립 선분이 아님

```
구조적 동치:
  ──H──┐        ──H──╲
        │V   ≡         ╲D  (D는 H-V 경계의 chamfer)
                         │V

H-D-H 구조 역시 H-V-H와 동치:
  ──H──╲              ──H──┐
         ╲D  ≡              │V(짧음)
         ╱                  │
  ──H──╱              ──H──┘
```

양 끝이 모두 H인 D → 짧은 **V로 치환 가능**  
양 끝이 모두 V인 D → 짧은 **H로 치환 가능**

> **D 구간 위에는 버텍스를 추가할 수 없다.**  
> D는 인접 H·V의 부속 장식이며 독립적인 경로 구간이 아니다.

## 3. 아트웍 오버레이: 개념

### 3-1. 구조

아트웍 오버레이는 **버텍스(Vertex) 목록**으로 정의된 H-V 선분 체인이며,  
각 H-V 꺾임에는 선택적으로 D chamfer가 삽입된다.

- 시작점: 출발 노드패드 위치
- 끝점: 도착 노드패드 위치
- 중간: 버텍스 N개 → 선분 N+1개 (각 선분은 H 또는 V)
- **최소 구성: 버텍스 2개** (아트웍 생성 시 자동 배치)

```
버텍스 2개 (HVH — 기본 시작 형태):

  fromPad=(x1,y1), toPad=(x2,y2), midX = (x1+x2)/2

  [패드A] ══════════ [V1] ══════════ [V2] ══════════ [패드B]
           H1(길이=midX-x1)  V(길이=y2-y1)  H2(길이=x2-midX)
                    V1=(midX,y1)   V2=(midX,y2)

버텍스 2개 (VHV — 수직 지배적일 때):

  midY = (y1+y2)/2

  [패드A] ════ [V1] ══════════════════════ [V2] ════ [패드B]
           V1        H(길이=x2-x1)               V2
         (x1,midY)                           (x2,midY)
```

**HVH vs VHV 결정 기준**: `|dx| >= |dy|`이면 HVH, `|dy| > |dx|`이면 VHV

### 3-2. 진입 방법

**베이스 선(직선 상태)** 을 우클릭 → **"아트웍 라우팅"** 클릭

```
[ 베이스 선 우클릭 컨텍스트 메뉴 ]
  ┌──────────────────────┐
  │  아트웍 라우팅        │  ← 아트웍 오버레이 생성 (버텍스 2개 자동 배치)
  │  이 트레이스 삭제     │
  └──────────────────────┘
```

아트웍으로 전환 시 패드 간 거리에 따라 HVH 또는 VHV가 버텍스 2개로 자동 생성된다.

### 3-3. 직선으로 초기화

아트웍 트레이스에서 "직선으로 초기화"를 선택하면:
- 현재 버텍스 전체 삭제
- HVH 또는 VHV로 **버텍스 2개를 새로 계산하여 재배치**
- 사용자 조형 이력이 초기화되고 자동 생성 상태로 복귀

> 베이스 직선(raw straight)으로 돌아가는 것이 아니라, 아트웍 상태를 유지하면서 초기 형태로 리셋된다.

## 4. 트레이스 레인 클릭 동작

| 동작 | 결과 |
|------|------|
| **1회 클릭** | 트레이스 레인 강조(밝게 표시), 선택 상태 |
| **2회 클릭** | 팝오버 윈도우 표시 (트레이스 정보·속성) |
| **우클릭** | 컨텍스트 메뉴 표시 (선택 여부와 무관하게 항상) |

### 우클릭 컨텍스트 메뉴

상태와 위치에 따라 메뉴 항목이 달라진다:

| 상태 | 위치 | 메뉴 항목 |
|------|------|-----------|
| 베이스 선 (직선) | 어디든 | 아트웍 라우팅 / 이 트레이스 삭제 |
| 아트웍 트레이스 | H 또는 V 구간 | **버텍스 추가** / 직선으로 초기화 / 이 트레이스 삭제 |
| 아트웍 트레이스 | D 구간 | 직선으로 초기화 / 이 트레이스 삭제 |

> 아트웍 상태의 트레이스에는 "아트웍 라우팅" 항목이 표시되지 않는다.  
> D 구간에는 버텍스 추가 불가이므로 해당 항목이 표시되지 않는다.

## 5. 버텍스 추가 및 조작

### 5-1. 버텍스 추가

H 또는 V 구간을 **우클릭** → 컨텍스트 메뉴 → **"버텍스 추가"** 클릭

추가 결과는 클릭된 구간의 방향에 따라 다르다:

#### H 구간 위 버텍스 추가 → HVH (V=0)

클릭 위치 P = (px, py) (H의 y좌표 위)

```
추가 전:  ...──H──────────────...
추가 후:  ...──H1──[V1]──V(=0)──[V2]──H2──...
                   V1=V2=(px, py)
```

- V1, V2가 동일 위치에 생성 (V 길이 = 0)
- 이후 V1을 위로 또는 V2를 아래로 드래그하여 V를 확장

#### V 구간 위 버텍스 추가 → VHV (H=0)

클릭 위치 P = (px, py) (V의 x좌표 위)

```
추가 전:  ...──V──────────────...
추가 후:  ...──V1──[V1]──H(=0)──[V2]──V2──...
                   V1=V2=(px, py)
```

- V1, V2가 동일 위치에 생성 (H 길이 = 0)
- 이후 V1을 왼쪽 또는 V2를 오른쪽으로 드래그하여 H를 확장

### 5-2. 버텍스 삭제

버텍스 **우클릭** → **"이 버텍스 삭제"**

- 전후 선분이 병합되어 H-V로 재연결
- D chamfer가 있었다면 함께 제거됨

### 5-3. 버텍스 드래그: 인접 선분 길이 변경

> **세그먼트 드래그** = 선분 자체가 이동  
> **버텍스 드래그** = 인접 선분의 **길이**가 변함

버텍스를 드래그하면 버텍스 위치가 이동하고, 전후 선분 길이가 조정된다.

- 4px(1그리드) 단위 스냅
- 선분 역전 허용: 버텍스가 인접 버텍스·패드를 넘어가도 연결 유지 (길이는 절댓값)

```
패드A ──(길이4)── V1  →  V1을 왼쪽으로 6 이동
패드A ──(길이2)── V1'  (V1'이 패드A 왼쪽에 위치, 방향 역전, 길이 2)
```

#### 특수 케이스: H-D-H에서 HD 버텍스 드래그

HDH = HVH와 동치. HD 버텍스 드래그 = **D(V)의 위치를 H 축 위에서 좌우로 이동**.  
H1 길이가 늘고 H2 길이가 줄거나, 반대로 조정됨.

```
H1──●──╲D╲──H2   (●=H1-D 버텍스)
         ╲
          ╲
드래그(오른쪽):
H1'──────●──╲D╲──H2'   (H1 늘어남, H2 줄어듦, D 위치 이동)
```

#### 특수 케이스: H-D-V-D-H에서 HD 버텍스 드래그

HD 버텍스 드래그 = **V의 X 위치를 H 라인 위에서 좌우로 이동**.  
H1 길이가 변하고, D1 및 V가 따라 이동. D2와 H2는 반대로 증감.

```
H1──●──╲D1╲──V──╱D2╱──H2   (●=H1-D1 버텍스)

드래그(오른쪽):
H1'──────●──╲D1╲──V──╱D2╱──H2'   (V 전체가 오른쪽으로 이동)
```

## 6. 세그먼트 드래그: H / V / D 각각의 동작

### 6-1. H 구간 드래그 (위아래 이동)

H 구간을 드래그하면 H 레인 자체가 **위아래**로 이동한다.

H가 이동하면 양 끝 버텍스의 Y가 고정된 상태이므로 V 구간이 조정된다.  
V-H 경계에 D chamfer를 삽입하거나 기존 D 크기를 조정한다.

- 끝단 버텍스가 존재하면: 해당 버텍스에서의 V 구간 길이가 H 이동량만큼 증감
- 끝단이 패드에 직접 연결된 경우: 새 V 구간이 생성되고 V-H 경계에 D가 삽입됨
- D가 이미 있으면: D 크기가 이동량에 맞게 조정됨

```
드래그 전:
  ────H────╲D╲───V───

H를 위로 Δ만큼 이동:
  ──H'──╲
          ╲D'╲    ← D 길어짐
               V' ← V 짧아짐
```

### 6-2. V 구간 드래그 (좌우 이동)

V 구간을 드래그하면 V 레인 자체가 **좌우**로 이동한다.

- 끝단 버텍스가 존재하면: 해당 버텍스에서의 H 구간 길이가 V 이동량만큼 증감
- 끝단이 패드에 직접 연결된 경우: 새 H 구간이 생성되고 H-V 경계에 D가 삽입됨
- D가 이미 있으면: D 크기가 이동량에 맞게 조정됨

```
드래그 전:
  ───H───╲D╲
              │V│

V를 오른쪽으로 Δ만큼 이동:
  ─────H'─────╲D'╲
                    │V'│
```

### 6-3. H-V 버텍스 드래그 (D chamfer 크기 조절)

H와 V가 만나는 버텍스를 드래그하면 그 경계의 D chamfer 크기가 변한다.  
(단, 이 버텍스는 H-D-V 구조의 세 구간 사이 경계점임)

- **코너 안쪽(직각 방향)**: D 커짐, 인접 H·V 줄어듦
- **코너 바깥쪽(둔각 방향)**: D 작아짐, 인접 H·V 늘어남
- D는 0 미만 불가
- **드롭 시 D 가로·세로 ≤ 2px**: D 제거, H·V 직접 연결

```
직각 방향 (D 증가):     둔각 방향 (D 감소 → 제거):
  ──H──╲                  ──H──┐
        ╲D'                     │V
          │V
```

### 6-4. D 구간 드래그

D의 동작은 **양 끝 구간의 종류**에 따라 다르다.

#### H-D-V 또는 V-D-H: D 크기 조절 (chamfer 증감)

- 드래그 방향으로 D가 커지거나 작아짐
- 인접 H·V 길이가 반대로 조정됨
- **드롭 시 D 가로·세로 ≤ 2px**: D 제거, H·V 직접 연결

#### H-D-H 또는 V-D-V: D 위치 슬라이딩

D = 짧은 V(또는 H)와 동치이므로, 드래그는 해당 V(또는 H)의 위치 이동이다.

- 드래그 방향으로 D 전체가 이동
- 양 끝 H(또는 V) 길이가 반대로 증감하여 연결 유지

```
H──D──H 구조에서 D를 오른쪽으로 이동:
  ──H────╲               ──H'──────╲
           ╲D →                     ╲D
           ╱                         ╱
  ──H────╱               ──H'──────╱
```

## 7. 아트웍 트레이스 선택 및 이동

### 7-1. 선택 방법

| 방법 | 설명 |
|------|------|
| **트레이스 클릭** | 해당 트레이스 단독 선택 |
| **Shift + 클릭** | 기존 선택에 추가 |
| **허공에서 좌→우 드래그** | 선택상자에 **완전히 포함된** 트레이스만 선택 |
| **허공에서 우→좌 드래그** | 선택상자에 **걸친 트레이스도 포함**하여 선택 |

### 7-2. 선택 후 이동 (Translate + Stretch)

선택된 트레이스를 드래그하면 전체가 이동한다.

- 선택된 트레이스의 모든 버텍스가 드래그 벡터만큼 일괄 이동
- 연결된 **노드패드 위치는 고정** (패드는 이동하지 않음)
- 패드에 인접한 첫/마지막 선분이 변화를 흡수하며 **Stretch**
- 내부 버텍스 간 선분은 이동 벡터 그대로 유지

```
이동 전:
  [패드A] ════════ [V1] ════ [V2] ════════════ [패드B]

트레이스를 오른쪽으로 이동:
  [패드A] ════════════ [V1'] ════ [V2'] ════ [패드B]
           ↑ Stretch                        ↑ Stretch
```

## 8. 버텍스·선분이 함수 도형과 겹칠 때

- 버텍스 또는 선분이 함수 노드 바운딩 박스와 겹치면 **경고 색상**으로 강조
- 자동 회피 없음 — 사용자가 직접 버텍스를 이동하여 해결
- 겹침 해소 즉시 경고 색상 제거

## 9. 노드패드 위치 이동

노드패드를 드래그하면 **함수 노드 외형선(바운딩 박스 테두리)** 을 따라 슬라이딩한다.

```
  ┌──────●──────────┐   ← 패드가 위쪽 외형선 위 이동
  │   함수 이름      ●   ← 패드가 오른쪽 외형선 위 이동
  │                  │
  └──────────────────┘
```

- 외형선 4변(상/하/좌/우) 어느 위치에든 가능
- 코너에서 4px 이내 배치 불가
- **4px(1그리드) 단위 스냅**
- 다른 패드와 최소 1그리드 간격 유지

패드 이동 시 연결 트레이스 업데이트:

| 트레이스 종류 | 업데이트 방식 |
|--------------|--------------|
| 직선 (베이스 선) | 새 패드 위치로 직선 재연결 |
| 아트웍 | 패드 인접 첫(또는 마지막) 선분만 Stretch, 나머지 유지 |

## 10. 데이터 구조

### Trace

```ts
type TraceState = "straight" | "artwork";

interface Trace {
  id: string;
  fromPad: PadId;
  toPad: PadId;
  state: TraceState;
  vertices: Point[];
  // artwork 상태에서:
  //   최소 버텍스 수 = 2 (HVH 또는 VHV)
  //   vertices[0] = fromPad 직후 버텍스
  //   vertices[N-1] = toPad 직전 버텍스
  //   선분 수 = vertices.length + 1
  //   선분[0]:  fromPad.position → vertices[0]
  //   선분[i]:  vertices[i-1]   → vertices[i]
  //   선분[N]:  vertices[N-1]   → toPad.position
  //
  // 각 선분의 H/V 방향 및 D chamfer 유무는 렌더링 시 동적 계산
}
```

## 11. 렌더링 우선순위

1. 함수 노드 도형 (항상 최상위)
2. 아트웍 오버레이 (버텍스 핸들 + H-V 선분 + D chamfer)
3. 베이스 직선 (아트웍 오버레이가 없을 때만 표시)
4. 노드패드 핸들 (드래그 중에는 최상위로 올라옴)

## 12. 결정 사항

- [x] D는 **장식용 chamfer** — 구조 선분 아님, H-V로 대체 가능
- [x] **D 구간 위에는 버텍스 추가 불가** / 우클릭 메뉴에서 "버텍스 추가" 항목 미표시
- [x] 아트웍 최소 구성: **버텍스 2개** (HVH 또는 VHV 자동 생성)
- [x] HVH vs VHV 결정: `|dx| >= |dy|`이면 HVH, `|dy| > |dx|`이면 VHV
- [x] **베이스 선** 우클릭 → "아트웍 라우팅" 진입 / 아트웍 트레이스에는 이 항목 없음
- [x] **"직선으로 초기화"**: 현재 버텍스 삭제 후 HVH/VHV 버텍스 2개로 재생성 (베이스 직선 복귀 아님)
- [x] 클릭 = 선택(밝게 강조) / 2회 클릭 = 팝오버 / 우클릭 = 컨텍스트 메뉴
- [x] **세그먼트 드래그** = 선분 자체 이동 / **버텍스 드래그** = 인접 선분 길이 변경
- [x] HDH에서 HD 버텍스 드래그 = D(V) 위치를 H 축 위에서 좌우 이동
- [x] HDVDH에서 HD 버텍스 드래그 = V의 X 위치를 H 라인 위에서 좌우 이동
- [x] H 구간 위 버텍스 추가 → V=0인 HVH 생성 (V1=V2 동일 위치)
- [x] V 구간 위 버텍스 추가 → H=0인 VHV 생성 (V1=V2 동일 위치)
- [x] 버텍스 이동 시 선분 역전 허용 (길이는 절댓값 처리)
- [x] H 드래그 → H 위아래 이동, 끝단 V 증감 (없으면 생성), V-H 경계에 D 삽입
- [x] V 드래그 → V 좌우 이동, 끝단 H 증감 (없으면 생성), H-V 경계에 D 삽입
- [x] H-V 버텍스 드래그: 직각 방향 → D 증가 / 둔각 방향 → D 감소 / 0 이하 불가
- [x] D 제거: 드롭 시 D 가로·세로 ≤ 2px이면 D 삭제, H·V 직접 연결
- [x] 선택: 클릭 / Shift+클릭 / 좌→우 드래그(완전 포함) / 우→좌 드래그(걸침 포함)
- [x] 선택 후 드래그 이동: 내부 버텍스 일괄 이동, 패드 인접 선분 Stretch
- [x] 노드패드 이동: 외형선 슬라이딩, 인접 선분 Stretch

# 트레이스 라우팅 전략

## 현재 문제

1. 트레이스가 함수 도형을 관통함
2. 트레이스끼리 겹침
3. 연결이 많은 함수가 중앙에 있어서 주변 트레이스가 혼잡

## 전략 원칙

### 원칙 0: 함수 배치 최적화
- 파일그룹 내에서 **노드패드 수가 많은 함수를 바깥쪽에 배치**
- 연결이 많은 함수가 외곽에 있으면 트레이스가 그룹 내부를 관통할 필요가 줄어듦
- 배치 순서 예시: 1행1열 → 2행8열 → 1행3열 → 2행6열 (지그재그로 분산)

#### 좌우 배치 규칙 (방향성 기반)
- **타 파일그룹으로 유출라인이 많은 함수** → 우측에 배치 (오른쪽 패드에서 그룹 바깥으로 나가는 경로가 짧아짐)
- **타 파일그룹에서 유입라인이 많은 함수** → 좌측에 배치 (왼쪽 패드로 그룹 바깥에서 들어오는 경로가 짧아짐)
- **본 파일그룹 내부로 유출라인이 많은 함수** → 좌측에 배치 (그룹 내부 좌→우 흐름)
- **본 파일그룹 내부로 유입라인이 많은 함수** → 우측에 배치 (그룹 내부 좌→우 흐름의 도착점)

### 원칙 1: 트레이스 비겹침
- 모든 트레이스는 서로 겹치지 않음
- 90도 또는 45도 각도로 교차(crossing)하는 것은 허용
- 평행 구간에서 일정 offset 유지

### 원칙 2: 함수 도형 비관통
- 트레이스는 함수 도형(노드 바운딩 박스)을 절대 통과하지 않음
- 노드 사이의 갭 또는 그룹 외곽 채널을 통해 라우팅

### 원칙 3: 노드패드 수 기준 순차 라우팅
- 노드패드가 가장 많은 함수의 트레이스부터 먼저 그림
- 먼저 그려진 트레이스는 이후 트레이스의 장애물로 취급
- 이렇게 하면 연결이 많은(=중요한) 함수의 트레이스가 최적 경로를 확보

## 실행 절차

```
1. 함수 배치 (layout)
   ├─ 각 함수의 총 연결 수 (인입 + 유출) 계산
   ├─ 연결 수 내림차순 정렬
   └─ 그룹 내 위치를 지그재그로 배정 (1행1열, 2행N열, 1행3열, ...)

2. 노드패드 할당 (pad allocation)
   ├─ 인입: 왼쪽 우선 → 위쪽 오버플로우
   └─ 유출: 오른쪽 우선 → 아래쪽 오버플로우

3. 트레이스 라우팅 (순차)
   ├─ 연결 수 기준 내림차순으로 함수 순회
   ├─ 해당 함수의 모든 엣지에 대해:
   │   ├─ 갭 채널 탐색 (노드 사이 공간)
   │   ├─ 갭이 막혀있으면 그룹 외곽 채널 사용
   │   ├─ 경로 확정 후 "점유된 채널"로 등록
   │   └─ 이후 트레이스는 점유된 채널을 피함
   └─ 결과: RoutedEdge[]
```

## 결정 사항

- [x] 점유된 채널 자료구조: **2D boolean 픽셀 그리드**
  - 캔버스 영역을 일정 해상도(예: 2px 단위)로 그리드화
  - 트레이스가 지나간 픽셀을 true로 마킹
  - 새 트레이스는 true 픽셀을 피하여 경로 탐색
  - 함수 도형 영역도 미리 true로 마킹 (관통 방지)

## 미결정 사항

- [ ] 그리드 해상도: 1px? 2px? 4px? (정밀도 vs 메모리/성능 트레이드오프)
- [ ] 같은 그룹 내 인접 함수 연결은 갭 통과 vs 외곽 우회 중 어느 것을 우선?
- [ ] 그룹 간 연결의 채널 위치 결정 기준은?
- [ ] 45도 구간을 어디서 사용할 것인가? (코너 chamfer? 대각선 바로가기?)
